# 55 — CI: benchmark baseline comparison

**Priority**: P2
**Status**: specified

## Problem

The `bench` CI job (TODO.roadmap/05) compiles the criterion suites
and runs them with `--quick` to catch build breakage. It does NOT
compare against a stored baseline, so a 10× regression in the
parser or crypto path slips through silently.

## Solution

Add a `bench-compare` job that runs only on PRs (not on main
pushes) and compares each suite against a baseline stored in
`docs/benches/baseline.json`. The baseline is regenerated by a
manual `cargo bench --save-baseline main` run on a quiet machine
and committed.

Threshold: regressions > 20% on any single bench fail the job.
Regressions < 20% emit a warning but pass. The 20% threshold is
deliberately loose — criterion's noise floor on shared CI runners
is ~10%, and tighter thresholds produce flaky failures.

Workflow snippet:

```yaml
bench-compare:
  name: Benchmark vs main
  runs-on: ubuntu-latest
  if: github.event_name == 'pull_request'
  steps:
    - uses: actions/checkout@v7
    - uses: dtolnay/rust-toolchain@stable
    - run: ./ci/install.sh
    - run: cargo bench --bench crypto --bench merkle --bench parser -- --benchmark main
```

The baseline file is small (~100 KB of criterion JSON); commit it
under `docs/benches/baseline.json` and refresh it whenever a perf
improvement lands.

## Acceptance criteria

- [ ] PR builds run bench-compare and surface regressions > 20%
- [ ] Baseline file committed and documented in docs/benches/
- [ ] At least one false-positive flake scenario tested (e.g.,
      bench on a noisy CI runner doesn't fail a clean PR)
